# HR demo model and report

**Status:** In progress
**Updated:** 2026-10-31

## Goal
Create a new demo HR semantic model and report to show to the HR team. It must look and behave like a real headcount and attrition solution, but run on synthetic data so no employee data is exposed. Use about 1,200 employees over 36 months, six departments and five locations.

## Scope
- Change: Add `src/hr.SemanticModel` and `src/hr.Report` (with `hr.pbip`), plus `Tests.Run` assertions in the new model.
- Keep unchanged: `sales` and `customer-comparison` artifacts, scripts and `parameter.yml` bindings for them.

## Approach
No HR data source exists in the repository. The developer approved synthetic data, including fictional gender and salary figures. The model generates synthetic data in Power Query with a fixed numeric seed, so refresh is repeatable and needs no external access. Names are fictional. The model implementation uses January 2023 through December 2025 for the 36 snapshots and a contiguous 2019 through 2025 calendar; the earlier dates support tenure and hire history.

Star schema (names follow the plural fact and singular dimension rule):
- `Employee` (dimension): employee key, fictional name, job title, level, gender, hire date, termination date, manager flag. Department and location do not change during this demo.
- `Department` (dimension): department key, department, division, cost center.
- `Location` (dimension): location key, city, country, region.
- `Calendar` (dimension): daily date table, marked as date table, with fiscal year and month columns for the February to January fiscal year.
- `Headcount` (fact): one row per employed person per month-end snapshot, with employee, department, location and date keys, FTE and annual base salary.
- `Movements` (fact): one row per hire or exit, with event date, employee, department, location, movement type and exit reason. Exits also have a tenure-at-exit band.

Measures live in the table they describe, in UPPERCASE, with format strings and descriptions in the Northwind Retail Group tone:
- `Headcount`: `HEADCOUNT` (distinct employees at the last snapshot in the period), `FTE` (sum at that snapshot), `AVERAGE HEADCOUNT` (average of month-end headcount across months in the selected period), `SALARY COST` (monthly annual base salary times FTE divided by 12, at the last snapshot).
- `Headcount`: `HEADCOUNT LY` for year over year comparison.
- `Movements`: `HIRES` and `EXITS` (event counts in the selected period), `ATTRITION RATE` (exits in the trailing 12 complete months divided by average monthly headcount across those same months; blank without 12 months of snapshots), and `ATTRITION RATE LY` (the same rate at the corresponding date a year earlier).

Report `hr`, using the Contoso theme and report rules, three pages:
- Overview: KPI cards (headcount, FTE, hires, exits, attrition rate), headcount trend, headcount by department.
- Attrition: attrition rate trend, exits by reason, exits by department and tenure band.
- Workforce: headcount by location, level and gender. Use at most one date slicer per page; put department and location in the filter pane.

For the model-only implementation, build locally, check the TMDL, deploy and refresh the semantic model in DEV, execute `Tests.Run` and independent live queries, then document under `docs/project/`. The report remains a separate approved step. Local BPA only runs on Windows; the repository scripts need `.env`, Fabric CLI and Azure CLI, which are unavailable in this environment, so use the authoring tool for deployment and live checks.

## Team rules
- Applies: [Semantic model rules](../../.agents/skills/team-practices/references/rules/semantic-model-rules.md): star schema, explicit measures with hidden base columns, measures in their own tables, consistent names, UPPERCASE measure names, a `Tests.Run` assertion per measure, descriptions using the company context. [Report rules](../../.agents/skills/team-practices/references/rules/report-rules.md): Contoso theme and design standards, no more than one slicer and 20 visuals per page, rendered review.
- Deviations: None planned.

## Acceptance checks
- Refresh succeeds and every live `Tests.Run` assertion returns boolean true; the repository test script may be used where its dependencies are available.
- `HEADCOUNT` at the last month equals the count of employees hired by and not terminated before that month end.
- For each full month in the snapshot range, prior month-end headcount plus that month's `HIRES` minus `EXITS` equals this month's headcount.
- `ATTRITION RATE` is blank when there is no headcount and totals are not sums of monthly rates.
- Every report page renders without visual errors in screenshots and follows the theme. Structural validation alone does not satisfy this check.
- Existing `sales` and `customer-comparison` artifacts are unchanged.

## Open questions
- The February to January fiscal year, rolling attrition definition, salary cost interpretation and static department/location are proposed demo definitions, not verified HR policy. Confirm or change before using this for real workforce reporting.
